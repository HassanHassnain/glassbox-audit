# B1 Progress Note

## Scope

Implemented B1 from `ROADMAP_AMBITIOUS_GLASSBOX.md`: `glassbox certify` and Intervention Audit Cards for frozen Glassbox intervention evidence.

## Implemented

- Added `glassbox_audit.certification`.
- Added `glassbox certify`.
- `certify` supports two modes:
  - `--artifacts` to card an existing frozen artifact directory;
  - `--config --output-artifacts` to run the normal frozen audit pipeline first, then card the resulting artifact.
- Added a candidate intervention spec interface for:
  - `artifact_method`;
  - `.pt` direction tensors;
  - `.pt` steering vectors;
  - SAE latent sets with local SAE checkpoints or SAELens identifiers;
  - callable import-path declarations.
- Candidate specs are validated, hashed, and included in the card with referenced-file hashes when available.
- Added card schema fields for model identity hash, corpus hash, preregistration hash, protocol counts, artifact hashes, external-transfer artifact hashes, candidate metadata, and the certified evidence method.
- Added per-rung verdicts for:
  - separation;
  - held-out causal effect;
  - specificity;
  - capability cost;
  - matched controls;
  - baseline superiority;
  - equivalence/inferiority tests;
  - optional transfer.
- `artifact_method` candidates certify the declared `interventions.json.causal_tests` row instead of always defaulting to SAE feature ablation.
- Matched-control p-values are read from `failure_analysis.json` for the SAE feature-ablation path and computed from stored random-control rows for direction-style candidates.
- Added optional external transfer artifacts through `--external-artifacts`; if supplied, transfer becomes part of the overall verdict.
- Added JSON, HTML, and dependency-free one-page PDF card rendering.
- Added optional `--sign`, which records a SHA-256 digest over the canonical card payload and git reference.
- Added `docs/CERTIFY.md`.
- Added `make certify`.
- Updated README artifact contract and command examples.
- Added focused certification test coverage.

## How

The implementation does not duplicate the experiment runner. Heavy model execution remains in `glassbox run` through the existing `run_audit` pipeline. `glassbox certify --config ...` calls that pipeline and then renders the card. `glassbox certify --artifacts ...` reads the frozen artifact files directly. This keeps B1 aligned with the existing train/validation/test wall, preregistration hash checks, matched controls, pair-clustered intervals, and all previously emitted evidence files.
