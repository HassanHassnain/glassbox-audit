## Implemented

- Public SAE runs use the configured SAELens layer instead of train-selected localization.
- Public SAE latents are ranked only from train activations at the mapped layer.
- Matched random-SAE controls for public SAE runs draw seeded random latent sets from the same public dictionary.
- `summary.json`, `manifest.json`, `protocol.json`, `sae_metrics.json`, and `interventions.json` now carry SAE source/control metadata.
- Public SAE runs write `results/sae-zoo/<model>_<release>_<sae_id>.json`.
- Public SAE runs refresh `results/sae-zoo/league_table.json` and `results/sae-zoo/league_table.md`.
- `refresh-controls` and external causal transfer reuse same-dictionary public SAE controls when the frozen `sae.pt` points to SAELens.
- Added the optional `sae-zoo` install extra and README/methodology notes.
- Added unit coverage for the SAELens adapter metadata and save contract using a tiny fake SAELens-like module.

## How

The public path loads `SAE.from_pretrained(release=..., sae_id=...)`, wraps it behind the same `encode`, `decode`, and `feature_direction` surface used by locally trained SAEs, and validates that the configured hook layer matches the public checkpoint metadata when available. Selection still uses `feature_table` on train final-token activations. Controls use `_public_sae_controls`, which samples random latent indices from the loaded public dictionary and evaluates the same steering and encode-zero-decode ablation controls.
